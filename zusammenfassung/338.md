# Simple Cloud in der Praxis: Rails-Deployment bei Farjo

Die Migration von AWS zu Hetzner Cloud zeigt, dass kleinere Cloud-Anbieter für spezifische Anforderungen eine ausgezeichnete Alternative darstellen können. Dirk Breuer und Lukas Domen berichten aus der Praxis, wie Farjo – eine dänische Ferienhausvermittlungsplattform – ihre Infrastruktur erfolgreich vereinfacht hat.

## Die Ausgangssituation

Farjo ist eine monolithische Rails-Anwendung mit einem kleinen Team von etwa sechs Entwicklern, das vollständig remote arbeitet. Das Besondere: Die Plattform verarbeitet große Mengen an Hintergrunddaten, benötigt aber kein komplexes Zahlungssystem. Diese Konstellation ermöglicht bewusst einfachere Entscheidungen in der Infrastruktur.

## Infrastructure-as-Code mit Terraform

Das Fundament bildet Terraform mit 650 Zeilen Code – unverändert seit fünf Monaten. Der Grund für diese Stabilität liegt in der Klarheit: Man beschreibt einmal, was Produktion ist, und dokumentiert gleichzeitig. Der Hetzner-Provider bietet alles Notwendige: VMs, Load Balancer, Storage und Firewalling. Das reicht vollkommen aus, um ein Staging-Environment zu schaffen, das produktionsnah ist.

## Automatisierung mit Ansible

Ansible sorgt mit etwa 1.000 Zeilen YAML dafür, dass neue Server eigenständig hochfahren können. Kernel-Updates, Docker-Konfiguration, Monitoring-Tools – alles wird automatisiert eingespielt. Eine bewusste Entscheidung: Ansible läuft nur beim initialen Boot. Änderungen erfordern neue Server statt nachträglicher Modifikationen.

## Docker und Swarm Mode

Ein unterschätztes Tool: Docker Swarm Mode (nicht das veraltete Docker Swarm). Es bietet genau eine Funktion, die sie brauchen – Zero-Downtime-Deployments. Neue Container werden hochgefahren, nach Health-Check wird Traffic umgeleitet, alte Container gehen runter. Mehr nicht, mehr braucht es auch nicht.

Die lokale Entwicklung nutzt Docker Compose, was den Abstand zwischen Entwicklung und Produktion minimiert. Deployments laufen via Capistrano – nur zwei Befehle: `docker-push` und `docker-stack-deploy`.

## Die Datenbank-Realität

Der kritischste Punkt: Postgres läuft auf einem Single-Node ohne Failover. Das ist eine bewusste Entscheidung, die sich in zwölf Jahren bewährt hat. Mit pgBackrest und Point-in-Time-Recovery auf S3-Speicher ist Datensicherheit gewährleistet, ohne Hochverfügbarkeit zu zahlen. Wartungs-Fenster zwischen 1 und 3 Uhr nachts reichen für Updates aus – und 70 Prozent Kostenersparnis sprechen für sich.

## Für wen passt dieses Setup?

Kleine Teams bis zehn Personen, die Infrastruktur selbst verantworten, profitieren am meisten. Voraussetzung: eine monolithische Architektur. Der Migrationaufwand zu anderen Providern bleibt überschaubar, da Terraform umgestellt und State migriert werden – hauptsächlich technische, keine konzeptionellen Änderungen.

## Fazit

Simple Cloud funktioniert nicht, weil sie billig ist, sondern weil sie für viele Anwendungsfälle ausreichend ist. Das Setup bei Farjo beweist: Langweilig ist ein Feature. Infrastruktur, die man nicht ständig anfassen muss, ist eine gute Infrastruktur. Mit Terraform, Ansible, Docker und PostgreSQL entsteht ein stabiles, nachvollziehbares System, das sich kleine Teams leisten können – zeitlich und finanziell.
