Solo-Folge von Eberhard Wolff, ausgelöst durch die Frage „Ich habe ein Repository für eine Tabelle – wie bekomme ich eine Anfrage über mehrere Tabellen hinein?“. Leitfrage: Soll das objektorientierte Domänenmodell oder das relationale Modell führen, und wie prägt die Wahl der Datenbank die Architektur? Wolff wiederholt taktisches DDD (Entities, Value Objects, Aggregates, Repositories, Services) und stellt ihm Normalisierung, Joins, Transaktionen über viele Tabellen und Ad-hoc-Abfragen gegenüber. Er zeigt, wo O/R-Mapper und JPQL das reine Objektmodell aus Performancegründen durchbrechen, warnt vor geteilten Datenbankschemata und ordnet Fowlers Patterns auf einem Spektrum ein: Domain Model mit Data Mapper, Active Record, Transaction Script, Row und Table Data Gateway. These: Ein einfacher HTTP-Import braucht kein DDD, eine Bestellabwicklung kein Transaction Script. Chatfragen zum anämischen Domänenmodell, zur Logik in Services und zu Funktionaler Programmierung werden beantwortet. Zum Schluss: Dokumentendatenbanken wie MongoDB, Aggregate als Dokument, leichtere Skalierung gegen verlorene Abfrageflexibilität, Volltextsuche als Ergänzung. Interessant für Entwickler:innen, die Persistenz und Domänenmodell entwerfen.
