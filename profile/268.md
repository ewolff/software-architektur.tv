Dritter Teil einer Reihe nach „LLMs in der Architektur?“ mit Eberhard Wolff und „Architektur-Theater“: Ralf D. Müller und Ingo Eichhorst lassen Claude Code die in der Vorwoche von Claude erstellte arc42-Architektur eines Wardley-Map-Editors implementieren. Leitfrage: Taugt eine KI-erzeugte Architektur als Grundlage für lauffähigen Code, oder gilt Garbage in, Garbage out? Eichhorst zeigt einen selbst generierten Konfigurator für das SPARC-Framework (Specification, Pseudocode, Architecture, Refinement, Completion), das im Kern ein parametrisierter Meta-Prompt ist, und startet Claude Code autonom in einem Devcontainer als Schutz gegen Prompt Injection. Das Ergebnis läuft in Minuten mit DSL und Live-Bearbeitung, aber ohne TDD, ohne Bezug auf arc42 und ohne Bedienelement für Verbindungen. Weitere Themen: widerspruchsfreie Prompts, Temperatur und Nichtdeterminismus, Plan-Modus, /init und /compact, Abo-Limits, Attribution von KI-Commits, Review-Aufwand bei großflächigen Änderungen, mehrere Varianten parallel erzeugen, Spezifikation als Steuerinstrument. Interessant für alle, die agentisches Coding auf Basis von Architekturdokumentation ausprobieren wollen.
