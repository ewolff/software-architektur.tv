Eberhard Wolff spricht mit Martin Lippert, der bei Broadcom die Spring Tools leitet, über das Model Context Protocol. Leitfrage: Wie bekommen LLM-Anwendungen Zugriff auf Kontext und Werkzeuge, ohne dass jede Anwendung jede Integration selbst baut? Lippert erklärt den Weg vom Prompt Stuffing über Function Calling zu MCP: Werkzeug-Server sprechen JSON-RPC, der Client – nicht das Modell – ruft sie auf und reicht Ergebnisse weiter, ähnlich wie beim Language Server Protocol. In einer Live-Demo bindet er mit Spring AI einen Dateisystem-Server ein, zeigt den MCP Inspector und einen eigenen Server in VS Code. Diskutiert werden, ob MCP Standard oder nur Anthropic-Projekt ist, wie das Modell das passende Werkzeug wählt (Beschreibungen als Prompt Engineering), wo Secrets bleiben, lokale vs. entfernte Server mit OAuth, Risiken durch ungeprüfte Server, minimale Berechtigungen, indirekte Prompt Injection über GitHub-Issues, RAG vs. MCP sowie Prompts, Resources und Sampling im Protokoll. Interessant für Entwickler:innen und Architekt:innen, die LLM-Anwendungen oder Agenten an eigene Systeme anbinden wollen.
