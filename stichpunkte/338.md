# Simple Cloud in der Praxis mit Dirk Breuer

## Wichtige Keytakeaways

- Simple Cloud Infrastruktur mit Terraform, Ansible und Docker Swarm ist für kleine Teams (bis ca. 10 Personen) völlig ausreichend und deutlich weniger komplex als Kubernetes.
- Ein Single-Node-Datenbank-Setup ohne High Availability ist eine vertretbare Entscheidung, wenn klare Maintenance-Windows existieren und Point-in-Time-Recovery mit pgBackrest implementiert ist.
- Monolithische Rails-Anwendungen lassen sich sehr effizient mit Docker Compose lokal und Docker Swarm Mode in Produktion betreiben.
- Trotz Preiserhöhungen bietet Hetzner Cloud nach wie vor etwa 70% Kostenersparnis gegenüber AWS mit vergleichbarer Funktionalität.
- Docker Swarm Mode ist nicht tot, sondern eine unterschätzte Alternative zu komplexeren Orchestrierungslösungen für viele Use-Cases.
- Infrastructure-as-Code mit Terraform ist essentiell, um Infrastruktur versionskontrolliert, testbar und dokumentiert zu halten.

## Behandelte Kernfragen

- Wie lässt sich eine Rails-Anwendung sinnvoll auf einer Simple Cloud wie Hetzner Cloud betreiben?
- Welche Rolle spielen Terraform, Ansible und Docker Swarm Mode in dieser Infrastruktur?
- Warum ist ein Single-Node-Datenbank-Setup für kleine Teams akzeptabel?
- Wie unterscheidet sich das Deployment von AWS zu einer Simple Cloud?
- Welche Alternativen zu Kubernetes gibt es für kleine, monolithische Anwendungen?
- Wie wichtig ist Infrastructure-as-Code für die Wartbarkeit und Dokumentation?

## Glossar wichtiger Begriffe

- **Infrastructure-as-Code**: Praxis, Infrastrukturressourcen durch deklarative Konfigurationsdateien (statt manueller Klicks) zu beschreiben und versionskontrolliert zu verwalten.
- **Docker Swarm Mode**: Native Orchestrierungsfunktion in Docker zum Verwalten und Aktualisieren von Containern mit Zero-Downtime-Deployments über einen einzigen Befehl.
- **Point-in-Time-Recovery**: Fähigkeit, eine Datenbank zu einem beliebigen Zeitpunkt in der Vergangenheit wiederherzustellen durch inkrementelle Backups (via pgBackrest).
- **Zero-Downtime-Deployment**: Strategie, neue Container-Versionen hochzufahren und den Traffic umzuleiten, bevor alte Versionen heruntergefahren werden.
- **pgBackrest**: Spezialisierte Backup-Software für PostgreSQL, die inkrementelle Backups und Point-in-Time-Recovery ermöglicht.
- **Rails Credentials**: Verschlüsseltes Secret-Management-System in Ruby on Rails, das Secrets in der Codebase speichert und mit Code-Changes deployt.

## Genannte Technologien

- **Terraform**: Infrastructure-as-Code Tool zur deklarativen Beschreibung und Verwaltung von Cloud-Ressourcen über APIs.
- **Ansible**: Konfigurationsmanagement-Tool zur automatisierten Server-Provisionierung und Konfiguration mittels YAML-basierter Playbooks.
- **Docker Swarm Mode**: Native Container-Orchestrierung in Docker für Simple-Cluster ohne externe Abhängigkeiten.
- **Capistrano**: Deployment-Tool ursprünglich aus der Rails-Welt zur automatisierten Ausführung von Befehlen auf mehreren Servern.
- **imgproxy (IMG-Proxy)**: Go-basiertes Tool zur dynamischen Bildoptimierung, Resizing und Format-Konvertierung (WebP, AVIF).
- **pgBackrest**: PostgreSQL-Backup-Tool mit inkrementellen Backups und Point-in-Time-Recovery zu S3-kompatiblem Storage.
