## Kernaussagen

- Vibe Coding führte bei Simon Martinelli zu nichts: nicht, weil es nicht funktionierte, sondern weil der Überblick fehlte. Nach ungefähr drei Monaten begann Simon neu, mit Use Cases.
- Eine Use-Case-Beschreibung mit Vorbedingungen, Ablauf, alternativen Abläufen, Business-Regeln und Nachbedingungen ist im Prinzip eine Taskliste für die KI.
- Requirements sagen, was das System machen soll. System Use Cases sagen, wie der Ablauf genau ist. User Stories dienen als Backlog.
- Bei User Stories stecken Abläufe und Business-Regeln in den Akzeptanzkriterien, häufig in loser Schüttung. Eine Ablaufbeschreibung gibt es nicht.
- Fullstack kommt der KI entgegen, egal in welcher Sprache: ein Ökosystem, Regeln für eine Sprache. Ein Use Case kennt keine Trennung zwischen Frontend und Backend.
- Self-contained Systems sind für Simon der beste Architekturstil für KI, weil der Kontext klein bleibt. Kleinerer Lösungsraum, besseres Resultat.
- Die Dokumentation liegt vollständig als Text vor: Markdown oder AsciiDoc, Diagramme in PlantUML und Mermaid.
- Aus dem Use Case entstehen Code und Tests. Das erlaubt Traceability: Welche Use Cases sind vollständig implementiert und getestet?
- System Use Case und Domänenmodell sind die Single Source of Truth, gepflegt in Markdown und Git, auch von den Product Ownern.
- KI ist nicht deterministisch. Bei Änderungen am Use Case generiert Simon nicht neu, sondern lässt Claude Code die Änderungen an Code und Tests anwenden.
- Der Prozess ist iterativ und inkrementell: Use Case für Use Case wird spezifiziert, das gehört zur Implementierung.
- SpecKit und Kiro sind für Simon eher task-driven als spec-driven und zu entwicklerlastig.
- Reverse Engineering mit KI zeigt, was ein Legacy-System heute macht, und liefert Diagramme, für die früher teure Werkzeuge nötig waren.
- KI-Agenten sind ein neues Werkzeug, das man erst lernen muss. In der Zusammenarbeit ähnelt der Agent einem Teammitglied: Auftrag geben, Resultat prüfen, von vorne.

## Glossar

- **AI Unified Process (AIUP)**: Simon Martinellis Prozess für Softwareentwicklung mit KI, inspiriert vom Rational Unified Process, iterativ und inkrementell
- **Use Case**: Beschreibung eines Ablaufs mit Akteuren, Vorbedingungen, Ablauf, alternativen Abläufen und Fehlerabläufen, Business-Regeln und Nachbedingungen
- **Self-contained System**: Architekturstil, bei dem die Anwendung aus unabhängigen Säulen besteht, die über Schnittstellen miteinander reden und einzeln deployt werden können
- **Vaadin**: Fullstack-Framework, bei dem der UI-Code in Java entsteht und der Komponentenbaum mit dem Browser synchronisiert wird
- **jOOQ**: Fluent API, um SQL zu schreiben, kein OR-Mapper
- **MCP-Server**: gibt der KI Werkzeuge an die Hand, im Gespräch etwa Playwright zum Fernsteuern des Browsers oder eine Suche in der Dokumentation
- **Skill**: kurze Beschreibung, was der Skill macht; die längere Beschreibung holt sich die KI erst, wenn sie den Skill braucht
- **Balkonarchitektur**: Simons Wort dafür, dass Entwickler an bestehende Logik anbauen, statt den ganzen Ablauf zu ändern
- **Browserless Testing**: Integrationstests auf UI-Ebene bei Vaadin, die nur den Java-Code testen und keinen Browser brauchen
- **Testpokal**: Verteilung mit vielen Integrationstests und relativ wenigen Unit-Tests, bei datenlastigen Applikationen passender als die Testpyramide
