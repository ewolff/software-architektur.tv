## Kernaussagen

- Das Paper „Artificial Intelligence in the Firm“ von Fiona Chen und James Stratton (Harvard University) wertet Daten von Jellyfish aus: 445 Millionen Work Events von 720.000 Menschen aus 655 Firmen. Es ist noch nicht peer-reviewed.
- Die Kernaussage: KI erzeugt deutlich mehr Code, aber das Ergebnis der Software-Entwicklung wird kaum besser, die Anzahl der Mitarbeitenden ändert sich nicht signifikant, und Code Reviews werden zum Bottleneck.
- Nach zwölf Monaten gibt es mit AI Assistants 30% mehr Lines of Code, mit AI Agents 44%. Lines of Code sind aber kein Maß für Produktivität: Code ist eine Liability, kein Asset. Wichtig ist der geschaffene Geschäftswert.
- Mit Agents werden 13,7% mehr Jira-Issues und 18 Prozent mehr Epics geschlossen, mit Assistants etwa gleich viele wie vorher.
- Mit Agents dauern Reviews 56,1% länger, sie blockieren öfter und bekommen mehr Kommentare. KI-Werkzeuge für Reviews nutzen fast 80 Prozent der Firmen, das Bottleneck bleibt trotzdem.
- Das Modell des Papers kennt nur Planen, Coden, Reviewen und Deployen, gemessen über Jira und GitHub. Eberhard hält es für zu einfach: Die Testphasen und das Deployment einer Continuous Delivery Pipeline fehlen, und das Modell nimmt an, dass Requirements unbegrenzt verfügbar sind.
- Die Daten haben einen Bias zu größeren, etablierten Firmen mit Software als Kerngeschäft, vor allem SaaS-Anbietern.
- Die Langfristprognose (plus 16,1% Output, minus 13,2% Beschäftigung) beruht auf dem Zusammenhang zwischen Preise und Nachfrage sowie auf fortgeschriebenem exponentiellem Wachstum der Leistungsfähigkeit der Hardware. Beides überzeugt Eberhard nicht.
- Eberhards eigene Vermutung: Der eigentliche Engpass der Softwareentwicklung liegt eher bei Requirements und vernünftiger Organisation.

## Behandelte Fragen

- Auf welchen Daten beruht das Paper, und welchen Bias haben sie?
- Wie stark steigen Lines of Code, Commits und Pull Requests mit AI Assistants und AI Agents?
- Taugen Lines of Code als Maß für Produktivität?
- Werden mit KI mehr Jira-Issues und Epics geschlossen?
- Verändert KI die Zahl der Beschäftigten in der Softwareentwicklung?
- Warum werden Code Reviews zum Bottleneck, und helfen KI-Werkzeuge für Reviews?
- Warum sollte mehr Nachfrage nach Software mehr Entwickler:innen brauchen?
- Welche Jobs bleiben, und wird Domänenwissen wichtiger?
- Welchen Qualitätsanspruch haben wir an Code, wenn auch menschlicher Code oft suboptimal ist?

## Glossar

- **AI Assistant**: Werkzeug, das Entwickler:innen in der IDE beim Schreiben von Code unterstützt
- **AI Agent**: KI, die selbstständig loslegt und Code schreibt, z.B. Claude
- **Jellyfish**: Software, mit der Firmen ihre Entwicklung managen; liefert die Daten des Papers
- **Bottleneck**: Engpass in einem Prozess, der den Durchsatz begrenzt
- **Preiselastizität**: Maß dafür, wie stark die Nachfrage auf eine Preisänderung reagiert
- **Vibe-Coding**: Code von einer KI erzeugen lassen, ohne ihn zu reviewen
